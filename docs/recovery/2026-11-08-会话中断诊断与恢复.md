## 四、项目记录修复

### 4.1 为什么不在应用运行时改库

1. 本轮任务运行在 Trae 进程内，改完无法重启应用验证，也无法在退出时阻止它把内存里的旧状态回写覆盖。
2. `state.vscdb` 在 14:32 仍被写入（文件 mtime），说明应用会周期性落盘，运行中写入结果不确定。
3. 改错的代价是项目列表与历史入口一起损坏，收益只是省一次手动操作，**风险明显高于收益**。

所以：**不动线上库**，改为提供脚本 + 手工两条路，由用户在退出应用后执行。

### 4.2 方案 A：运行脚本（推荐）

脚本：`docs/recovery/apply-quizlab-project.py`

```bash
# 1. 完全退出 Trae CN（Cmd+Q，确认 Dock 图标消失）
pgrep -f "Trae CN" || echo "已退出"
# 2. 执行
python3 /Users/amixc/MyWorkSpace/CodeStaction/QuizLab/docs/recovery/apply-quizlab-project.py
# 3. 重新打开 Trae CN，检查左侧项目栏
```

脚本会做这些事（每一步都有输出）：

1. 检测 Trae CN 是否仍在运行，在运行就拒绝执行；
2. 把 `state.vscdb` 与 `state.vscdb.backup` 备份到
   `~/Library/Application Support/Trae CN/User/globalStorage/backup-quizlab-<时间戳>/`；
3. 把 `6ae85aa3a3e476d41d9344ee` 的路径从 LeoMath 改成 QuizLab，同步更新 `name` 与 `available`；
4. 若已有别的项目条目指向 QuizLab，则只删除失效的 LeoMath 条目，不产生重复；
5. 回读校验：打印改后的值、确认没有重复的 QuizLab 条目、确认没有残留 LeoMath 路径；
6. 校验失败时自动用备份回滚。

保留原项目 ID 是有意为之：会话记录按项目 ID 归档，换个新 ID 等于把老会话（含 `bfadb54a`）继续留在孤岛里。

### 4.3 方案 B：纯手工（不改库）

1. 打开 Trae CN，在项目栏找到 `LeoMath`，右键 → 移除/删除项目（它已经标为不可用）。
2. `文件 → 打开文件夹…`，选 `/Users/amixc/MyWorkSpace/CodeStaction/QuizLab`。
3. 关闭并重新打开应用一次，确认新项目留在项目栏。
4. 之后在项目里打开历史会话，`语文阅读命题（正文复用）` 应恢复可读。

代价：手工方式会生成一个新的项目 ID，老的会话仍挂在旧 ID 下，可能仍看不到历史。**如果目标是保住老会话历史，用方案 A。**
