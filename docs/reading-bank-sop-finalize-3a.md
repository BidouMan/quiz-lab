# 阅读题库定稿 SOP：原文—题目—答案

> 版本：v1.0（2026-11-09，三上基线）
> 适用范围：语文课外阅读题库的采集、清洗、命题、答案、质检、挂载、校准。
> 唯一流程源：本文件。**换年级不复制本文件**，只新增 `data/reading-catalog/grades/<年级>.json`。
> 配套文件：
> - 年级参数：`data/reading-catalog/grades/3a.json`
> - 断点状态：`data/reading-catalog/progress/3a.json`
> - 考点体系：`docs/reading-skills-3a.md`
> - 质量计划：`docs/quality-plan-3a.md`
> - 质检脚本：`tools/reading-intake/quality_gate.py`
> - 导出脚本：`tools/reading-intake/export_mounted.py`

## 0. 一句话启动

### 0.1 启动语模板（直接复制）

```text
按三上流程做三下。

1. 先读 docs/reading-bank-sop-finalize-3a.md（流程）、data/reading-catalog/grades/3b.json（参数）、data/reading-catalog/progress/3b.json（断点）。
2. 3b.json 不存在时，从 3a.json 复制，只允许改 SOP §1.3 标「必须重估」的字段；改前把差异项列给我确认。
3. 从 progress 的 stage / nextBatch 继续；每批 20 篇。
4. 每批只汇报六个数字：新增入池 / 过门禁 / 挂载 / 淘汰 / 本批编号区间 / 下批起始编号。
5. 遇到以下情况必须停下问我：主题归属拿不准、同一篇有 ≥2 个候选来源、正文清洗需要补字或改字、目标篇数达成、素材池连续 2 批零新增、外部站点连续 3 次抓取失败。
6. 其余按 SOP 自主执行；不得跳过 quality_gate.py，不得手改 mounted.ts。
```

### 0.2 首轮读取顺序

| 顺序 | 文件 | 读什么 | 不读会怎样 |
| --- | --- | --- | --- |
| 1 | `docs/reading-bank-sop-finalize-3a.md` | 全部判定规则与回退条件 | 容易把「清洗」做成「改写」 |
| 2 | `data/reading-catalog/grades/<年级>.json` | 字数、题量、考点、主题、来源、去重阈值 | 用错年级的阈值 |
| 3 | `data/reading-catalog/progress/<年级>.json` | stage、nextBatch、failures、blockers | 重复已完成的批次或跳过失败项 |
| 4 | `data/reading-catalog/quality-gate.jsonl` | 当前正式题库的 pass/fail 与难度 | 误把待修稿当正式稿 |
| 5 | `tools/reading-intake/quality_gate.py` | 规则实现（与本文不一致时按 §10 处理） | 凭记忆写阈值 |

### 0.3 执行边界

- 本 SOP 只管「一篇短文从素材到入库」。采集站点的抓取实现不在本文，只约束入池判定。
- 任何一步的产物都必须落盘；对话里说过的结论不算记录。
- 机器能判的用脚本，脚本判不了的必须标【人】并留复核意见。

## 1. 年级参数表

### 1.1 配置文件

- 位置：`data/reading-catalog/grades/<年级>.json`。
- 命名：`3a` = 三年级上册，`3b` = 三年级下册，`4a` = 四年级上册。
- 原则：**流程共用一份，参数一册一份**。不要把阈值写进脚本或对话。

| 字段 | 三上取值 | 作用 | 对应脚本/规则 |

### 1.3 换年级：必须重估 vs 可直接沿用

| 字段 | 换年级 | 重估依据 | 低年级调整方向 |
| --- | --- | --- | --- |
| `grade` / `gradeName` | 必改 | 年级标识 | — |
| `minHanzi` | **必须重估** | 目标年级近 3 年真题正文汉字的中位数与最低值；不能把三上的 250 直接套到一年级 | 一、二年级 100–150；三、四年级 250；五、六年级 400+ |
| `collectMinHanzi` | **必须重估** | 取 `minHanzi × 0.6` 左右，只做采集粗筛 | 随 `minHanzi` 同步下调 |
| `maxHanziHint` | 重估 | 目标年级真题最长篇 | 低年级 300–400 |
| `questionsPerPassage` | **必须重估** | 低年级注意力与书写量有限，题量必须下调 | 一、二年级 3–4；三、四年级 3–5；五、六年级 4–5 |
| `questionsPerPassageDefault` | 重估 | 取区间中位 | 低年级取 3 或 4 |
| `objectivePerPassage` / `subjectivePerPassage` | **必须重估** | 低年级以选择、填空为主；高年级简答占比上升 | 一、二年级约 4∶1；三、四年级约 3∶2；五、六年级约 2∶3 |
| `skillsVersion` | 可沿用 | SK1–SK7 覆盖小学阅读主要能力；初中需扩展（论证方法、表达效果等） | 小学阶段不改枚举，只改篇目配比 |
| `requiredSkillAny` / `requiredSubjectiveAny` | 可沿用 | 与能力体系绑定，不随年级变 | 低年级可把 SK3 主观题放宽为「说出词意」 |
| `themes` | 可沿用 | 九类主题对小学通用 | 低年级提高童话、寓言占比，不改枚举 |
| `batchSize` | 可沿用 | 20 篇是一轮人工能审完的上限 | 低年级可降到 15 |
| `dedup.windowHanzi` | 重估 | 低年级短文多，20 字窗占比过高会误杀 | 一、二年级改 15 字 |
| `dedup.coverThreshold` | 重估 | 短文重复更常见，阈值需更严 | 一、二年级 0.85 |
| `dedup.longestRunCheck` | 可沿用 | 20 字连续重合对任意年级都算同文 | — |
| `sources` / 优先级 | **必须重估** | 站点可用性、版权、页面结构会变；每学期复验一次 | 不可用的标 `blocked` / `excluded`，不要静默重试 |
| `targetPages` | **必须重估** | 单元数 × 每单元目标篇数；不是固定 268 | 低年级可减少篇数、增加题内小问 |
| `difficultyTarget` | 重估 | 低年级「难」占比应下降 | 一、二年级约 40/45/15 |
| `mountedWhitelist` | 可沿用 | 前端字段契约；改字段必须同步 `types.ts` 与导出脚本 | — |

### 1.4 新年级建配置的动作

1. 复制 `data/reading-catalog/grades/3a.json` 为 `<年级>.json`。
2. 只改 §1.3 标「必须重估」的字段；其余保持。
3. 新建 `data/reading-catalog/progress/<年级>.json`，`stage` 置 `harvest`，`counts` 全 0。
4. 在 `AGENTS.md` 的必读路径里能按 `<年级>.json` 找到配置；不需要改 SOP。
5. 跑一次 20 篇校准（§7），校准不通过不得放量。

## 2. 原文定稿

### 2.1 允许的清洗（只动形式，不动内容）

| 动作 | 允许做什么 | 证据要求 | 例子/脚本 |
| --- | --- | --- | --- |
| 去卷面题头 | 删「十、课外阅读。(11分)」「阅读短文，回答问题」等 | 原页可见 | RD-378 删题头后正文 296 字 |
| 去页眉页脚 | 删页码、装订线、姓名/班级/学号/成绩栏 | 原页可见 | `intake.py clean` 的 `FURNITURE` |
| 去重复篇名 | 正文首段与 `title` 完全相同则删首段 | 两段逐字相同 | RD-645/646/569 |
| 切段 | 按原文段落、①②③、句末标点切 | 不得并段、不得拆句 | `intake.py clean` 断行合并 |
| 全半角/引号规范化 | `,`→`，`、`()`→`（）`、`..`→`……` | 只改形式 | `intake.py normalize` |
| OCR 形近字纠正 | 改回原文可查证的字（同页另一处、原卷答案、权威版本） | 必须能指出依据 | `redline.py` 只允许可查证改字 |
| 删混入内容 | 删邻篇正文、答案页、习作声明、广告、二维码 | 与原篇无关即可删 | 审计 E 类 |
| 表格转写 | 按单元格逐字转成 `｜` 分隔行，首行表头 | 列数与表头一致 | `reading-table` 版式 |
| 保留出处注 | 「（选自《X》）」保留，排小字，不计正文汉字 | 原页有 | 模板 `（选自` 分支 |

### 2.2 绝对红线（命中任一，不得入库）

| 红线 | 判定 | 处置 |
| --- | --- | --- |
| 补写正文 | 原卷缺句/缺段，凭上下文或想象补 | 弃稿，或换完整来源；不得补 |
| 改写/润色 | 换词、调语序、缩句、扩句、统一文风 | 改回原文；无法还原则弃稿 |
| 拼接 | 把两篇/两段拼成一篇 | 除非原卷本身是多材料组合（标 SK7），否则弃稿 |
| 按常识猜缺字 | OCR 缺字处按语义猜一个 | 找原页核对；核对不到就留缺字标记并弃稿 |
| 改事实 | 改人名、地名、数字、量词、时间、颜色 | 一律禁止 |
| 正文夹答案 | 把答案、解析、评分点写进正文 | 删除；无法区分则弃稿 |
| 为出题删原文 | 删掉「用不上」的段落或句子 | 禁止；题目必须适配全文 |
| 降难度删词 | 把所谓超纲词替换成简单词 | 禁止；超纲词不进题干即可 |

### 2.3 改完之后必须回查（逐条过）

| # | 检查 | 通过标准 | 谁做 |
| --- | --- | --- | --- |

| 2 | 段落数 | ≥3 段 | 【机】`gate.py` |
| 3 | 首段重复 | 首段 ≠ `title`；重复已删 | 【机】字符串比对 |
| 4 | 卷面残留 | 无「姓名/班级/学号/装订/第 N 页/参考答案/分值」 | 【机】正则扫全篇 |
| 5 | 引号配对 | `“` 与 `”` 数量相等；`（` 与 `）` 数量相等 | 【机】计数 |
| 6 | 段落序号 | ①–⑩ 连续、不重号 | 【机】人工规则 |
| 7 | 表格完整 | 每行 `｜` 数量 = 表头列数；无空表头 | 【机】`｜` 计数 |
| 8 | 原页抽对 | 随机抽 3 处，与原图/原页逐字一致 | 【人】只能人看 |
| 9 | 同篇判定 | 通读确认没有混入第二篇、没有缺句 | 【人】只能人看 |

| 12 | 清洗留痕 | §6.3 的 `review` 已写清洗动作和依据 | 【人】写，【机】检查非空 |

### 2.4 常见混入与处理

| 现象 | 例子 | 处理 |
| --- | --- | --- |
| 正文是答案页 | 整页「参考答案」 | 弃稿 |
| 一篇里混两篇 | 前半《掌声》后半《马蜂窝》 | 弃稿；除非能按原卷切成分材料并标 SK7 |
| 正文挖空 | 「矛的进攻（ ）」 | 弃稿，不猜空 |
| 知识梳理/词句训练 | 单元知识点清单、关联词训练 | 弃稿，不是短文 |
| 试卷前段 | 基础题语段、拼音填空语段 | 弃稿 |
| 文言/诗歌 | 《楚人学舟》《做一个最好的你》 | 弃稿 |
| 纯图依赖 | 优惠券、地图、海报只有图 | 无文字版则弃稿 |

### 2.5 原文定稿的通过条件

同时满足才算「正文锁版」：

1. §2.3 的 1–7、11 全部【机】通过；
2. §2.3 的 8–10 由【人】签字；
3. `review` 写明来源、清洗动作、字数；
4. `progress` 的该篇状态从 `clean` 进入 `lock-text`。

## 3. 题目定稿

### 3.1 三种来源的准入条件

| 来源 | `origin.action` | 定义 | 准入条件 | 允许动作 |
| --- | --- | --- | --- | --- |
| A 原题原样 | `保留` / `原题` | 原卷题干、选项、答案都能用 | 原题干问点不变；答案可用；只差格式 | 只做标点/全半角/占位符规范化 |
| C 原题修补 | `修补` / `修正` | 原题干和考查角度保留 | 能用原题干 + 原答案回答；只缺锚点、评分点、干扰项或 1 题 | 补锚点、补评分点、改干扰项、问答改四选一、补 1 题 |
| B 自命题 | `新命` 或无 `origin` | 没有可用原题，或修补后问点已变 | 原题不可用；按 §3.4 写题 | 按 T1 全新命题 |

### 3.2 保留原题时允不允许改题干

| 改动 | 允许 | 记录 |
| --- | --- | --- |
| 补「文中」「第 N 自然段」等范围限定 | 允许 | 仍记 `保留` |
| 把「______」改成 `（ ）` 占位 | 允许 | 仍记 `保留` |
| 全半角、标点、引号统一 | 允许 | 仍记 `保留` |
| 修正题干引错的原文句 | 允许 | 记 `修正`，note 写原句与改法 |
| 改问点（问什么变了） | 不允许 | 必须转 `新命` |
| 改正确项/答案 | 不允许 | 必须转 `新命` 或 `修正` |
| 改选项语义、换干扰项 | 只允许补/换干扰项，不改正确项 | 记 `修正` |

### 3.3 修补到什么程度转自命题

命中任一，`origin.action` 必须写 `新命`，不得写 `修补`：

1. 原题干要学生做的动作变了（如「画线」变「赏析」）；
2. 原答案不能再用（正确项换了、答案范围变了）；
3. 考点 SK 变了；
4. 原题两个小问被合并，第二问没有独立评分依据；
5. 原题本身与正文不符（段落号错、人物错），需要重写问法。

一句话判据：**能用原题干 + 原答案回答 → 修补；否则 → 自命题。**

### 3.4 自命题题干写法约束

| # | 约束 | 一眼判定 | 检查 |
| --- | --- | --- | --- |
| 1 | 指明作答范围 | 题干含「文中」「第 N 自然段」「这句话」之一 | 【人】 |
| 2 | 指明动作 | 含摘录/概括/说明/体会/判断/比较等动词 | 【人】 |
| 3 | 一题一问 | 问号 ≤1；多问必须分点 | 【机】问号计数 + scoring 条数 |
| 4 | 多问分点 | 题干 ≥2 个问号 → `scoring` ≥3 条或 `answer` 用「；/①②③」分点 | `check_answers.py` |
| 5 | 不给答案线索 | 题干不出现「总分总」「承上启下」等术语 | `compare_origin.py` TERMS |
| 6 | 引原文逐字 | 引号内 ≥5 汉字，且能在正文逐字找到 | `gate.py` / `redline.py` |
| 7 | 填空可判 | `（ ）` 数 = `blanks` 数；每个答案逐字在正文 | R7 |
| 8 | 选择可判 | 4 个互异选项；`answer` 0–3；`explain` 含 ≥6 汉字原文引句 | R8 |
| 9 | 干扰项同质同域 | 四项同一类事物/同一语法位置 | 【人】R10 只判长度与凑数词 |
| 10 | 选项长度比 | 最长/最短 ≤2.0 | R10 |
| 11 | 正确项分布 | 同篇不得连续 3 题同一位置；全库四位接近 1/4 | R10 + 导出层重排 |
| 12 | 不用开放问法兜底 | 「你觉得/你认为/联系生活/想象一下」不能是唯一问法 | `compare_origin.py` OPEN_RE |

### 3.5 超纲术语与模板题干

**禁止出现在题干和选项里的术语**（`compare_origin.py` 的 `TERMS`、`review_batch.py` 的 `TERMS`）：

```text
总分总、总分、分总、借景抒情、托物言志、承上启下、首尾呼应、过渡句、
点明中心、动静结合、详略、象征、铺垫、伏笔、侧面描写、正面描写、
表达方式、修辞手法、段落作用、环境描写
```

- 答案本身也不得是术语。学生必须认识术语才能答对 → 改问法。
- 例：RD-589#2 的四个术语选项改为直白表述后通过。

**禁止的模板题干前缀**（`review_batch.py` 的 `TEMPLATES`）：

```text
短文主要写……
文中写“X”，……
短文第 N 段……
短文最后……
```

- 处理：换成具体对象 + 具体动作，例如「草原第 4 自然段写了哪些动物？请依次摘录」。

### 3.6 题型配比与考点

| 项目 | 三上要求 | 脚本 |
| --- | --- | --- |
| 题量 | 3–5 题，默认 5 | R3 |
| 客观题 | ≥2 题（选择/填空） | R5 |
| 主观题 | ≥1 题（简答） | R5 |
| 考点数 | ≥3 类 | R4 |
| 必含考点 | SK2 或 SK4 | R4 |
| 主观题考点 | 至少 1 道 SK3 或 SK5（SK4 问「体会/感受/心情/品质」可计入） | R4 + `EMOTION_RE` |
| 纯抄写/纯记忆 | 最多 1 题；≥2 题 fail；不得是唯一主观题 | R6（「唯一主观题」需【人】判） |
| 难度 | 易 ≤350 字；中 350–550；难 >550 或含 SK6/SK7 | R12 仅记录 |

### 3.7 题目定稿前检查表

1. 【机】`quality_gate.py --ids <ID>` 无 R1–R13 命中；
2. 【机】每题 `skill` 字段是七个中文考点之一；
3. 【机】每题 `origin.action` 是 `保留/原题/修补/修正/新命` 之一；
4. 【机】选择题 4 项互异、长度比 ≤2.0、无「以上都对/无法判断」；
5. 【机】填空题占位数 = `blanks` 数，答案逐字在正文；
6. 【机】简答 `scoring` 2–3 条，≥2 条含 ≥4 汉字原文锚点；
7. 【人】每题问点清楚、不给答案线索、无术语；
8. 【人】干扰项同质同域，不能靠语气/长度排除；
9. 【人】同一篇 5 题不重复考同一个点，SK 分布合理；
10. 【人】难度标注与正文长度、SK 匹配。

## 4. 答案定稿

### 4.1 三类题的「可判定」标准

| 题型 | 可判定标准 | 机器检查 | 人工检查 |
| --- | --- | --- | --- |
| 填空 | 每个 `blanks` 字符串在正文逐字出现；`（ ）` 数 = 答案数；一个空只有一个可接受答案 | R7；`gate.py` 答案在原文 | 答案是否真正回答问题；同义写法是否漏收 |
| 选择 | 4 项互异；`answer` 0–3；`explain` 含 ≥6 汉字原文引句；只有正确项被原文支撑 | R8 / R10 | 引句是否真的支撑正确项；干扰项是否同域 |
| 简答 | `scoring` 2–3 条；≥2 条含 ≥4 汉字原文锚点；必须有 `answer`；答案 ≤120 字；无禁用词；多问分点 | R9 / R13；`check_answers.py` | 评分点是否覆盖答案要素；开放表述是否可接受 |

**禁用词**（`check_answers.py` 的 `BANNED`，答案里出现即不合格）：

```text
略、见解析、言之有理即可、答案不唯一、自由发挥
```

### 4.2 评分点必须指回原文哪一句

评分点写法固定为：**「答出『原文引句』＋说明」**，引句 ≥4 汉字且逐字在正文。

| 不合格写法 | 合格写法 |
| --- | --- |
| 说出草原美丽 | 答出草原「广阔而又美丽」，如「满眼绿色，一直铺向远方」 |
| 体会到作者感情 | 答出对草原的喜爱和赞美，引「还是个欢腾的世界」 |
| 写出人物品质 | 答出「乐于助人」，引「他背起老奶奶过马路」 |

- 引号内原文 ≥4 汉字，`quality_gate.py` 的 `scoring_anchors` 会计数。
- 只写「言之有理即可」「意思对即可」→ 不算可回溯，R9 fail。
- 一条评分点只对应一个作答要素；不要把两个要素塞进一条。

### 4.3 答案唯一性验证

| 题型 | 验证动作 | 通过标准 |
| --- | --- | --- |
| 填空 | 在正文中搜索该答案串 | 只出现 1 次，或上下文唯一指向该空 |
| 选择 | 逐项回原文找支撑 | 只有正确项有原文支撑；其余 3 项无支撑或被原文否定 |
| 简答 | 用参考答案逐条对评分点 | 每条评分点都能在参考答案里找到对应句 |
| 简答 | 反向检查 | 学生按参考答案作答，5 题至少 4 题能得满分；得不了的说明评分点超纲 |

- 填空若出现 2 次以上：改题干限定范围（「第 2 自然段中」），不换答案。
- 选择若 2 项都有支撑：说明题干问点不清，回 §3.3 转自命题。

### 4.4 开放题怎么处理才不算含糊

开放问法（`compare_origin.py` 的 `OPEN_RE`）：

```text
联系自己/你的/生活、结合实际、谈谈你的、你的看法、你觉得、你认为、
想象一下、还可以、如果是你、劝一劝、说一说你
```

开放题必须同时满足三条，否则改成闭合问法：

1. 题干明确要求「结合文中哪一处」；
2. `scoring` 第 1 条必须是原文锚点，第 2–3 条才是个人表述；
3. `answer` 给出「文中依据 + 一种合理表述」，并写清可接受的替代方向（不写「略」）。

例：RD-378 第 5 题「摘录一句写草原欢腾的句子，再说说它让你感到草原怎样」——先摘录（可判），再说感受（开放但有原文依据）。

### 4.5 答案定稿前必须过的检查项

| # | 检查 | 通过标准 | 谁做 |
| --- | --- | --- | --- |
| 1 | 主观题答案覆盖 | 每道 `short` 都有非空 `answer` | 【机】R13 |
| 2 | 答案长度 | ≤120 字 | 【机】`check_answers.py` |
| 3 | 禁用词 | 不含 §4.1 五个词 | 【机】 |
| 4 | 原文依据 | 答案含 ≥8 汉字原文片段或引号原句 | 【机】粗检 |
| 5 | 多问分点 | 题干 ≥2 问 → 答案含「；」或①②③ | 【机】 |
| 6 | 评分点锚点 | 2–3 条，≥2 条含 ≥4 汉字原文 | 【机】R9 |
| 7 | 评分点覆盖 | 每条评分点在答案里有对应 | 【人】 |
| 8 | 语义支撑 | 引句真的支撑答案，不是碰巧命中 | 【人】只能人看 |
| 9 | 填空答案 | 逐字在正文，一空一解 | 【机】R7 |
| 10 | 选择解析 | `explain` 引句 ≥6 汉字，且支撑正确项 | 【机】R8；语义【人】 |
| 11 | 家长可核对 | 家长拿答案能在正文找到依据 | 【人】抽 2 题 |
| 12 | 答案与解析分离 | `explain` 是解析，`answer` 是核对答案，不混写 | 【人】 |

## 5. 判定顺序与回退

### 5.1 固定顺序：先锁正文，再出题，最后写答案

| 阶段 | 输入 | 动作 | 出口条件 | 产物 |
| --- | --- | --- | --- | --- |
| 0 harvest | 来源页/PDF/图片 | 抓正文、建 `sourceId` | 字数 ≥ `collectMinHanzi`、非重复 | 素材池 `passages.jsonl` |
| 1 clean | 素材 | 按 §2.1 清洗 | §2.3 的 1–7 通过 | `clean.txt` / 草稿段落 |
| 2 lock-text | 清洗稿 | 定稿正文、写 `charCount`/`sources` | §2.5 全部通过 | `quiz-drafts/<ID>.json` 的 `paragraphs` |
| 3 questions | 锁版正文 | 按 §3 出题/修补/自命题 | §3.7 全部通过 | `questions` |
| 4 answers | 题目 | 按 §4 写答案/评分点 | §4.5 全部通过 | `answer` / `scoring` / `explain` |
| 5 gate | 单篇稿 | `quality_gate.py --ids` | 无 fail 规则 | `quality-gate.jsonl` |
| 6 mount | pass 稿 | `export_mounted.py` | 导出无中止 | `mounted.ts` |
| 7 calibrate | 抽样 | 按 §7 盲评 | 胜率/缺陷率达标 | `work/calibration/` |

**为什么不能反过来**：所有答案锚点、选择题 explain、填空答案都指向正文。先出题后定正文，正文一改，锚点全废，必须重做答案。题目阶段发现正文缺陷，只能回阶段 1，**不能靠改题绕过**。

### 5.2 什么情况下必须回上一步重来

| 发现 | 回退到 | 不允许的做法 |
| --- | --- | --- |
| 正文缺句、混篇、错字影响答案 | 阶段 1 clean | 在题干里绕开缺句 |
| 原文找不到答案支撑 | 阶段 3 questions（换题） | 补写正文来支撑答案 |
| 评分点锚点不足 | 阶段 4 answers（补引句） | 把概括短语硬说成原文 |
| 填空题答案在正文出现 2 次 | 阶段 3（加范围限定） | 换一个正文没有的答案 |
| 选择题 2 项都有支撑 | 阶段 3（重写问点） | 随便定一个正确项 |
| 门禁 R2/R1 | 直接下架，不回退 | 改 `charCount` 或删来源标签 |
| 导出报主题/skill/题量错 | 阶段 3 或 5（修字段） | 改导出脚本白名单绕过 |
| 同一篇回退 ≥2 次 | 停止，标 `blocked`，问人 | 继续死循环 |

### 5.3 每步失败怎么记录

写进 `data/reading-catalog/progress/<年级>.json` 的 `failures`，一条一次：

```json
{
  "id": "RD-xxx",
  "stage": "answers",
  "rule": "R9",
  "detail": "第 3 题评分点 1/2 可回溯",
  "attempt": 1,
  "nextAction": "回阶段 4 补原文引句；若原文无引句则回阶段 3 换题",
  "at": "2026-11-09"
}
```

- `failures` 只增不删；修好后把 `nextAction` 改为 `resolved` 并记 `resolvedAt`。
- 同时在该篇 `review` 末尾追加一行：`【回退】2026-11-09 R9：第 3 题补锚点后复检通过`。
- 不得只在对话里说「已修好」。

### 5.4 禁止的绕过方式

- 改 `quality_gate.py` 的阈值让自己过；
- 改 `charCount` / `sourceCharCount` 凑字数；
- 把 `origin.action` 从 `新命` 改成 `保留` 洗白；
- 手改 `mounted.ts` 加一篇未过门禁的稿；
- 把不达标篇目留在 `quiz-drafts/` 但不写 `progress`。

## 6. 单篇定稿的记录格式

### 6.1 落盘位置

| 文件 | 内容 | 谁维护 |
| --- | --- | --- |
| `data/reading-catalog/quiz-drafts/<ID>.json` | 单篇唯一真源：正文、题目、答案、来源、复核记录 | 人 + 脚本 |
| `data/reading-catalog/quality-gate.jsonl` | 门禁结果（派生） | `quality_gate.py` |
| `data/reading-catalog/downlisted.json` | R1/R2 下架清单（派生） | `quality_gate.py --write-downlist` |
| `data/reading-catalog/quiz-drafts-rejected.jsonl` | 淘汰记录（派生） | 同上 |
| `data/reading-catalog/progress/<年级>.json` | 断点状态、失败项、批次日志 | 每批手写更新 |
| `src/data/chinese/readings/mounted.ts` | 前端挂载（派生） | `export_mounted.py` |
| `tools/reading-intake/work/calibration/<日期>/` | 盲评键、评分表、结论 | 校准人 |

### 6.2 单篇字段（必填/选填）

| 字段 | 必填 | 取值/格式 | 说明 |
| --- | --- | --- | --- |
| `id` | 是 | `RD-\d{3}` | 全库唯一、不复用 |
| `term` | 是 | `3A` | 年级学期 |
| `kind` | 是 | `extracurricular` / `in-text` | 课内/课外 |
| `scope` | 是 | `extracurricular` / `in-text` | 与 kind 一致 |
| `sourceId` | 是 | `szx-0039` / `ns21-...` | 能回指素材池 |
| `title` | 是 | 原文篇名 | 不用「阅读短文」 |
| `theme` | 是 | 九类之一 | 见 §1.2 |
| `status` | 是 | `verified` | 未定稿不写 verified |
| `sourceCharCount` | 是 | 整数 | 源切分单元汉字数 |
| `charCount` | 是 | 整数 | 正文本体汉字数（≥250） |
| `paragraphs` | 是 | 字符串数组 | ≥3 段 |
| `sources[]` | 是 | `{label, locator, url?}` | label+locator 必填 |
| `review` | 是 | §6.3 模板 | 不能为空 |
| `questions[]` | 是 | 3–5 题 | 见下 |

题目字段：

| 题型 | 必填字段 | 判定要点 |
| --- | --- | --- |
| `choice` | `type, stem, options[4], answer(0–3), explain, skill` | explain 含 ≥6 汉字引句 |
| `fill` | `type, stem, blanks[], explain, skill` | `（ ）` 数 = blanks 数；答案在正文 |
| `short` | `type, stem, scoring[2–3], answer, skill` | ≥2 条锚点；answer 非空 |

每题还应带 `origin`：

```json
"origin": {
  "action": "保留 | 原题 | 修补 | 修正 | 新命",
  "original": "原卷题干（保留/修补时写）",
  "note": "改了什么、依据是什么"
}
```

### 6.3 `review` 模板（照抄填空）

```text
2026-11-09 命题。素材：<passages.jsonl 第 N 行 / sourceId>（源自 <URL>）。
源切分单元 <N> 汉字（正文 <X>＋原题 <Y>）。
清洗：<删题头/去重复篇名/切段/OCR 纠错>，<一字未改 | 改了哪几个字及依据>；正文 <Z> 汉字。
题目来源：保留 <a>／修补 <b>／自命题 <c>；原卷答案 <可用/缺失>。
逐题：第 1 题 <保留/修正/新命>（<依据>）；第 2 题 …；第 5 题 …。
配比：客观 <o>∶主观 <s>；题型 <choice/fill/short>；考点 SK<n>（<n> 类）。
答案：主观题参考答案已写；锚点句「<引句>」；开放题 <处理方式>。
判定：quality_gate pass（R1–R13 无命中）；人工复核 <结论/待办>。
【回退】<日期> <规则>：<处理结果>（没有就不写）
```

合格样例：`data/reading-catalog/quiz-drafts/RD-378.json` 的 `review` 字段。

### 6.4 派生文件不要手改

- `quality-gate.jsonl`、`downlisted.json`、`quiz-drafts-rejected.jsonl`、`mounted.ts` 都能由脚本重建。
- 手改会导致下次重跑被覆盖，且无法解释差异。
- 需要改门禁结果 → 改 `quiz-drafts/<ID>.json` 后重跑脚本。

## 7. 校准方法：同一篇原卷题 vs 自命题

### 7.1 目标与频率

- 目标：判断自命题是否达到原卷题水平，并定位差距类型，不是给单题打分。
- 频率：每新增 50 篇一次；**换年级必须先做一次 20 篇基线**。
- 样本量：同一篇同时有原题（A/C）和自命题（B）的篇目 ≥20 篇；三上当前 A/B/C 混篇 182 篇，足够抽样。

### 7.2 可重复步骤

| 步 | 动作 | 命令/产物 |
| --- | --- | --- |
| 0 | 生成指标基线 | `python3 tools/reading-intake/compare_origin.py --json > tools/reading-intake/work/compare-origin.json` |
| 1 | 选样 | 从混篇中按编号等距抽 20 篇；每篇保留 A 组题组与 B 组题组 |
| 2 | 去标识 | 删除 `id/sourceId/sources/review/origin/score/status/skills/difficulty`；题号重编；A/B 顺序随机 |
| 3 | 建键 | 随机码 ↔ 真实来源映射写入 `work/calibration/<日期>/key.json`，评价者不可见 |
| 4 | 评分 | 每套题按 §7.3 评分卡打分；每题必须写至少 1 条缺陷 |
| 5 | 二选一 | 同一篇 A/B 两套，必须选「整体更好」的一套，不允许「持平」 |
| 6 | 猜来源 | 评分者先写「我猜这套是原卷/自命题」及依据；依据为语气/排版/分值的标注「非质量依据」 |
| 7 | 汇总 | 胜率、各维度均分、缺陷类型分布、来源猜测准确率 |
| 8 | 结论 | 写入 `work/calibration/<日期>/result.md`，并更新 `compare_origin` 指标解读 |

### 7.3 评分卡（每题 0/1/2）

| 维度 | 0 | 1 | 2 | 谁判 |
| --- | --- | --- | --- | --- |
| 可判定性 | 答案不唯一/评分点不可执行 | 基本可判，边界模糊 | 答案唯一或评分点可直接执行 | 【人】 |
| 原文支撑 | 无原文依据 | 有引句但支撑弱 | 引句直接支撑答案 | 【人】为主，脚本辅助 |
| 干扰项 | 荒谬/可语气排除 | 同域但长度或语气有破绽 | 同质同域，必须回原文 | 【人】 |
| 问法清晰 | 含术语/多问无分点 | 能读懂但有歧义 | 范围、动作、作答量都清楚 | 【人】 |
| 考点匹配 | skill 标错 | 大致匹配 | 与 SK 定义一致 | 【人】+ 脚本 |
| 难度适龄 | 明显超纲/过易 | 边界 | 符合本年级 | 【人】 |

- 每题总分 0–12；低于 8 分必须在缺陷栏写「改法」。
- **每题必须指出缺陷**：写「无缺陷」视为无效评分，退回重评。
- 评分卡不替代门禁；门禁是硬规则，评分卡判质量。

### 7.4 强制二选一

- 同一篇的 A 组与 B 组必须选一组「整体更适合给学生练」，不允许「差不多」。
- 若认为持平，必须先各写 1 条缺陷，再选一组；选不出 → 交第二评价者。
- 统计口径：B 胜率、A 胜率、B 缺陷类型 Top 3。

### 7.5 去标识与防语言风格猜来源

| 风险 | 做法 |
| --- | --- |
| 通过 `id`/`review` 猜来源 | 删除全部元数据，文件名用随机码 |
| 通过分值「（3分）」猜原卷 | 删除 `score` 与题干里的分值 |
| 通过排版猜来源 | 统一为同一 JSON → 同一排版模板；A/B 不并排 |
| 通过问法风格猜来源 | 保留原文问法，不做「标准化改写」；要求评分者把「语气/风格」标为非质量依据 |
| A/B 相邻导致对比锚定 | 打乱题组顺序，同一篇 A/B 不相邻 |
| 来源猜测准确率过高 | 若 >70%，判去标识失败，重做第 2 步 |

### 7.6 人工与模型结论不一致时怎么取舍

| 冲突类型 | 取舍 | 理由 |
| --- | --- | --- |
| 硬规则（锚点、长度比、选项数、术语） | 以脚本为准，人工复核数据是否有误 | 硬规则可复现 |
| 语义支撑（引句是否真的支持答案） | 以 2 名人工一致结论为准 | 脚本只看字符串命中 |
| 干扰项是否同域 | 人工为准 | 脚本只判长度与凑凑词 |
| 难度/适龄 | 人工为准 | 脚本按字数与 SK 粗分 |
| 人工之间不一致 | 第三人裁决，记入 `result.md` | 不取平均 |
| 模型与人工不一致 | **以人工为准**，模型意见只作缺陷线索 | 模型不承担合格判定 |
| 模型单独给「合格/不合格」 | 不采纳 | 模型只能列缺陷 |

### 7.7 校准通过标准

| 指标 | 通过线 | 不通过的处理 |
| --- | --- | --- |
| 来源猜测准确率 | ≤70% | 去标识失败，重做 |
| B 组胜率 | ≥40% | 自命题整体不合格，回 §3 修 |
| B 组「原文支撑」均分 | ≥1.6/2 | 补锚点/换题 |
| B 组「干扰项」均分 | ≥1.5/2 | 重写干扰项 |
| B 组缺陷 Top 1 | 不是「不可判定」 | 若是，先修答案唯一性 |
| 无效评分（写「无缺陷」） | 0 条 | 退回重评 |

### 8.2 中断后恢复的标准动作

1. 读 `progress/<年级>.json`，看 `stage`：
   - `blocked` → 先处理 `blockers`，处理不了就问人，不得继续。
   - `done` → 不要重跑；除非用户明确要求新一轮。
2. 用磁盘现状核对 `counts`（§8.3）；不一致时**以磁盘为准**，更新 progress 并记 `notes`。
3. 从 `nextBatch.startId` 取下一批：

```bash
python3 tools/reading-intake/review_batch.py --start RD-xxx --count 20
```

4. 逐篇按 §2–§4 处理，处理完跑：

```bash
python3 tools/reading-intake/quality_gate.py
python3 tools/reading-intake/export_mounted.py
```

5. 更新 progress：`counts`、`batchLog`、`failures`、`nextBatch`、`lastCommit`。
6. 提交本批改动（只提交本批相关文件）。

## 9. 停止条件与交接

| 停止条件 | 判定 | 动作 | 交接物 |
| --- | --- | --- | --- |
| 目标篇数达成 | `counts.mounted ≥ targetPages` | 停止新增；跑一次全量门禁 + 校准；`stage=done` | 终验报告、progress |
| 素材池枯竭 | 来源全部 `exhausted`，或连续 2 批新增 0 | 停止；列出已扫来源与剩余候选；`stage=blocked` | 素材缺口清单 |
| 连续多批零新增 | 连续 3 批 `added=0` | 停止并问人：换来源/降阈值/改目标 | 三批日志 |
| 需要人决策的分类归属 | 主题拿不准、同篇 ≥2 来源、版权不明、正文需补字 | 单篇 `blocked`，不阻塞其他篇；≥3 篇同类问题则整批停 | `blockers` + 具体篇目 |
| 外部站点不可用 | 连续 3 次 403/antispider/超时 | 标 `blocked` 或 `excluded`，切换下一优先级；不静默重试 | 来源状态、失败截图/日志 |
| 门禁通过率异常 | 连续 2 批 pass 率 <50% | 停止放量，回 §7 校准，查是阈值错还是命题质量差 | 校准报告 |

- 每次停止都要写 `progress.notes`，说明停在哪、为什么、下一步建议。
- 不允许「静默空转」：没有新增也要写批次日志（`added: 0` + 原因）。
