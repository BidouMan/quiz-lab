# Mac 微信客户端批量导出公众号文章链接：可行性实测结论

**结论先行：不可行。** 在「不破解、不导出聊天内容、不上传数据」的前提下，这台 Mac 上的
微信客户端无法批量取出已关注公众号的历史文章（标题 + URL）。两条独立阻断：

1. **本地消息库读不到**：`~/Library/Containers/com.tencent.xinWeChat/...` 受 macOS
   应用数据保护（TCC），`ls` / `head` / `stat` 中的读取操作与 Finder 复制全部返回
   `Operation not permitted`；授予「完全磁盘访问权限」后才可能读取。
2. **即使能读也解不开**：微信 4.x 本地库为 SQLCipher 4 加密，密钥只存在于进程内存，
   取得密钥需要内存扫描或调试器下断点，属于破解，明确越界。
3. **界面侧没有链接出口**：微信网页容器不向 macOS 辅助功能暴露任何正文节点
   （实测整窗只有 6 个节点），无法枚举标题/链接；客户端菜单也没有「复制链接」
   「在浏览器打开」这类入口。

因此不提供采集工具，也不给未经验证的替代做法。

---

## 实测环境

| 项 | 值 |
| --- | --- |
| 系统 | macOS 27.0.1（26A434） |
| 微信 | 4.1.15（`client_version=4066647863`） |
| 数据根目录 | `~/Library/Containers/com.tencent.xinWeChat/Data/Documents/xwechat_files/` |
| 账号目录 | `wxid_***_3bed`（本文档隐去完整 id） |

## 路径 1：本地数据库直读（不可行）

用 `lsof -p <WeChat pid>` 可看到进程实际打开的文件（只暴露路径，不读内容）：

- `.../wxid_***_3bed/db_storage/message/biz_message_0.db`（1,232,896 字节）
- `.../db_storage/message/biz_message_0.db-wal`（201,912 字节）
- `.../db_storage/contact/contact.db`、`favorite/favorite.db`、`message/message_*.db`
- `.../all_users/login/wxid_***/key_info.db`（12,288 字节）

按微信 4.x 目录结构，公众号消息一般落在 `biz_message_*.db`；但**内容无法读取，未能实测证实**。

读取尝试全部被系统拒绝：

```
$ ls  .../db_storage/message/
ls: ...: Operation not permitted

$ head -c 16 .../biz_message_0.db
head: ...: Operation not permitted

$ stat -f "%N %z bytes" .../biz_message_0.db
.../biz_message_0.db 1232896 bytes      # 只有元数据可用
```

Finder 复制同样失败（说明不是终端沙箱问题，而是系统级应用数据保护）：

```
sandbox_extension_issue_file failed for .../key_info.db: 1 (Operation not permitted)
Finder 遇到一个错误：AppleEvent 已超时。(-1712)
```

加密判断：`key_info.db` 与 `db_storage/` 的分库结构符合微信 4.x 的 SQLCipher 4
（AES-256-CBC + HMAC-SHA512，密钥仅驻留进程内存）公开实现；由于文件内容读不到，
**这一条是依据公开资料与结构推断，未做文件头实测**。即便获得磁盘权限，取密钥仍需
内存扫描/调试注入，属破解。

## 路径 2：界面自动化（不可行）

- **辅助功能树为空**：用 System Events / JXA 遍历微信网页窗口，只得到
  `AXWindow ×1、AXButton ×3、AXGroup ×2`（共 6 个节点），没有正文、没有 `AXLink`、
  没有 `AXWebArea`。公众号文章列表与文章页对辅助功能完全不可见，无法按标题枚举，
  更拿不到链接。
- **截图 + 坐标点击可用**：屏幕录制权限可用，`screencapture` 正常；按坐标点击能打开
  公众号主页和文章页（已实测打开一篇文章并抓到窗口截图）。但「能点开」不等于「能取链接」，
  见下一条。
- **没有链接出口**：网页容器地址栏只显示页面标题，不显示 URL；容器右上角「…」菜单实测为
  `刷新 / 调整文字大小 / 查找… / 浏览记录 / 下载内容 / 关闭全部标签页`；公众号主页「…」
  菜单为 `私信 / 推荐给朋友 / 设为星标 / 不再关注`；应用菜单（文件/编辑/显示/窗口）
  也没有导出或「在浏览器打开」。文章页底部只有 `点赞 / 分享 / 推荐 / 写留言`。
- 结论：逐篇手工复制链接也无法自动化，且不满足「批量」。

（测试期间该机同时有其他应用/会话抢占前台与桌面空间，坐标点击不稳定；但上述菜单项与
辅助功能节点数是在微信窗口实际可见时直接读取/截取的，属于有效实测。）

## 路径 3：分享 / 在默认浏览器打开 / 导出（不具备）

- 没有「在浏览器打开」入口（见路径 2 的菜单实测）。
- 微信 4.x 的聊天记录「迁移与备份」只针对会话，不覆盖公众号历史推送，也没有可解析的
  明文导出物。
- 客户端不存在「公众号历史文章导出」功能。

## 需要什么条件才能成立（均越界，故不做）

1. 用户在系统设置里给工具授予「完全磁盘访问权限」——仍只解决读文件。
2. 从微信进程内存提取每库密钥并解密 SQLCipher——属破解，明确不做。
3. 使用微信网页版/公众号后台登录态走 `profile_ext` 接口——这与本机客户端无关，
   已有调研记录见 `WECHAT_LOGIN_ROUTE.md`（需要用户自己的登录态，且受风控限制）。

## 建议的替代路线（非本机客户端）

- 浏览器登录 `mp.weixin.qq.com` 后，按 `WECHAT_LOGIN_ROUTE.md` 的方式用自己的登录态
  低频翻页；或用户手动在浏览器中滚动历史列表，导出 `content_url` 列表再离线抓正文。
- 手机端微信「公众号 → 历史消息」逐篇分享到文件传输助手，再在桌面端整理——属于人工流程，
  不是批量工具。
